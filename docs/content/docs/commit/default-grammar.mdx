---
title: Default grammar
description: What a [commit] section without slots enforces.
---

A `[commit]` section with no `slots` still enforces the shape of a
header, without restricting any spelling. It behaves like:

| Slot        | Shape          | Required |
| ----------- | -------------- | -------- |
| `keywords`  | `word`         | yes      |
| `(...)`     | `( )`          | no       |
| `[...]`     | `[ ]`          | no       |
| `modifiers` | `symbols`      | no       |
| `separator` | `symbol`       | yes      |

followed by a space and a description. Messages use the names in the
first column.

| Header                          | Result                                         |
| ------------------------------- | ---------------------------------------------- |
| `add(lib)[int]: standard style` | Valid                                          |
| `feat(api)!: conventional style` | Valid                                         |
| `yolo(whatever)> ship it`       | Valid                                          |
| `wip!!~ kitchen sink`           | Valid                                          |
| `feat!(api): x`                 | Invalid: `!` is read as the separator          |
| `no separator here`             | Invalid: ``expected `modifiers` ``             |

This is useful for keeping headers parseable while a team settles on
its spellings. `default-ignores` still applies:

```toml
[commit]
default-ignores = false
```
