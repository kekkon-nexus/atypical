---
title: Default grammar
description: What a commit section enforces when it declares no slots.
---

A `[commit]` section without `slots` enforces the header shape with no
restricted spellings:

| Slot        | Shape     | Required |
| ----------- | --------- | -------- |
| `keywords`  | `word`    | Yes      |
| `(...)`     | `( )`     | No       |
| `[...]`     | `[ ]`     | No       |
| `modifiers` | `symbols` | No       |
| `separator` | `symbol`  | Yes      |

The slot names in this table appear in messages.

| Header                           | Result                                  |
| -------------------------------- | --------------------------------------- |
| `add(lib)[int]: standard style`  | Valid                                   |
| `feat(api)!: conventional style` | Valid                                   |
| `yolo(whatever)> ship it`        | Valid                                   |
| `wip!!~ kitchen sink`            | Valid                                   |
| `feat!(api): x`                  | Invalid: `!` is parsed as the separator |
| `no separator here`              | Invalid: ``expected `modifiers` ``      |

`default-ignores` applies as usual.
