---
title: Ambiguity
description: Grammars rejected before any header is read.
---

A grammar is checked when it is loaded. If it cannot be lowered, or if
two of its slots could not be told apart on some header, `commit-lint`
exits `1` with the error and lints nothing.

An optional slot does not separate its neighbours: since it may be
absent, the slots on either side are checked against each other too.

## Malformed slots

| Error                                                      | Cause                                                    |
| ---------------------------------------------------------- | -------------------------------------------------------- |
| ``slot `x` needs exactly one of `kind`, `delimiters` or `one-of` `` | None of them, or more than one                  |
| ``slot `separator` is a `symbol`, so it cannot match `::` `` | A listed spelling the kind can never match             |
| ``` `gap` does not apply to slot `emoji` ```               | A key in the wrong place on a [`one-of`](/docs/commit/one-of) |

## Indistinguishable slots

Each row is a minimal grammar that fails, and a way out.

### A run followed by the same kind

```toml
[[commit.slots]]
name = "type"
kind = "word"

[[commit.slots]]
name = "subtype"
kind = "word"
```

```txt
`type` takes the whole run, leaving nothing for `subtype`
```

A word reads every word character there is, and so does unrestricted
`symbols`. Put a delimited slot or a symbol between them.

### Spellings sharing a prefix

```toml
[[commit.slots]]
name = "modifiers"
kind = "symbols"
values = ["!", ":"]

[[commit.slots]]
name = "separator"
kind = "symbol"
values = [":"]
```

```txt
`modifiers` and `separator` both start with `:`
```

Bare slots match by prefix, so neighbours need spellings that do not
start alike.

### A closed set before an open one

```toml
[[commit.slots]]
name = "modifiers"
kind = "symbols"
values = ["!"]

[[commit.slots]]
name = "separator"
kind = "symbol"
```

```txt
`separator` takes anything, `modifiers`'s spellings included
```

Restrict the second slot's `values` too.

### The same delimiters twice

```toml
[[commit.slots]]
name = "scope"
delimiters = ["(", ")"]

[[commit.slots]]
name = "ticket"
delimiters = ["(", ")"]
```

```txt
`scope` and `ticket` carry the same delimiters
```

Delimiters are matched wherever they sit, so give each slot its own
pair. Sharing only the opener is fine.

### Overlapping options

```txt
`emoji` and `shortcode` can start on the same input
```

See [One of](/docs/commit/one-of#options-must-not-overlap).

### An optional bare slot behind a gap

```toml
[[commit.slots]]
name = "emoji"
kind = "symbols"
values = ["✨"]
required = true
gap = true

[[commit.slots]]
name = "keywords"
kind = "word"
```

```txt
`keywords` is optional after a gap, so it can take the start of the description
```

The space after the gap is also the description's, so an optional word
there would swallow the first word of the description. Make it
`required`, or make it delimited.
