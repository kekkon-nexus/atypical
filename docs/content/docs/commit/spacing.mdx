---
title: Spacing
description: gap and tight, for headers with spaces inside the prefix.
---

By default the prefix has no spaces: slots sit against each other and
the only space is the one before the description. `gap` and `tight`
allow headers like gitmoji's, where a space follows the emoji.

## `gap`

`gap = true` owes one space after the slot. The next slot that is
present takes it, or the description does if none is. An absent slot
passes the debt on.

## `tight`

`tight = true` attaches the slot to what precedes it with no space,
and leaves any owed space to the slot after it.

## Worked example

The [gitmoji preset](/docs/presets/gitmoji) is an `intention` with
`gap`, an optional `scope`, and an optional `tight` separator:

| Header                   | Reading                                                |
| ------------------------ | ------------------------------------------------------ |
| `✨ Add a feature`       | No scope or separator, so the description takes the gap |
| `✨ (auth): Add a feature` | `scope` takes the gap; the separator attaches after it |
| `✨: Add a feature`      | The tight separator attaches; the description takes the gap |
| `✨(auth): Add a feature` | Invalid: `scope` is not tight, so it needs the space  |
| `✨  Add a feature`      | Invalid: only one space is allowed there               |

## Caveat: openers after a gap

Once its opener follows the space, an optional delimited slot behind a
gap is committed to. So with an optional `(...)` there, a description
that starts with `(` is read as that slot.
