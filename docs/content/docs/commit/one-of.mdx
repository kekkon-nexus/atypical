---
title: One of
description: A slot that takes exactly one of several forms.
---

A `one-of` slot matches exactly one of its options. Each option is
shaped like a slot of its own, with a `name`, one of `kind` or
`delimiters`, and optional `values`:

```toml
[[commit.slots]]
name = "intention"
required = true
gap = true

[[commit.slots.one-of]]
name = "emoji"
kind = "symbols"
values = ["✨", "🐛"]

[[commit.slots.one-of]]
name = "shortcode"
delimiters = [":", ":"]
values = ["sparkles", "bug"]
```

This accepts `✨ add a feature` and `:sparkles: add a feature`, but not
both forms at once (`✨:bug: x`).

## Which keys go where

`required`, `gap` and `tight` say whether and how the slot appears, so
they stay on the outer slot. `values` say what one form accepts, so
they go on each option.

| Mistake                         | Error                                         |
| ------------------------------- | --------------------------------------------- |
| `values` on the outer slot      | `` `values` does not apply to slot `intention` `` |
| `required` on an option         | `` `required` does not apply to slot `emoji` `` |
| `gap` or `tight` on an option   | `` `gap` does not apply to slot `emoji` ``    |
| A `one-of` inside an option     | `` `one-of` does not apply to slot `emoji` `` |

## Options must not overlap

Two options that could start on the same input are rejected, since the
one tried second would be unreachable there. An unrestricted `symbols`
emoji next to a `:shortcode:` overlaps, because `:` is a symbol:

```txt
`emoji` and `shortcode` can start on the same input
```

Listing the emoji closes the set and removes the overlap, which is
what the [gitmoji preset](/docs/presets/gitmoji) does.
