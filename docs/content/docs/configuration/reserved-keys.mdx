---
title: Reserved keys
description: name, drop and before, in every named array.
---

Inside an array whose every entry has a `name`, three keys are merge
directives rather than data:

| Key      | Type    | Meaning                                         |
| -------- | ------- | ----------------------------------------------- |
| `name`   | string  | What other layers match the entry on            |
| `drop`   | boolean | Remove the entry with this name                 |
| `before` | string  | Place this entry ahead of the one named         |

`drop` and `before` are consumed while loading, so a tool's schema
never sees them. `name` stays on the entry, and `commit-lint` uses it
in its messages.

This holds for every section and every tool, not only `[commit]`.
A tool adding its own named array cannot give these keys another
meaning.

A directive of the wrong type, such as `drop = "yes"`, is left in
place, so the tool's schema rejects it as an unknown key instead of it
quietly meaning `false`.
